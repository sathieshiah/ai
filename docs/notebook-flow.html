The Seven-Model Sweep

Two decoding experiments over the same seven architectures, the same prompt and the same harness. One picks a token every step. The other never picks at all. Everything else is held identical so the difference belongs to the decoder.

TL;DR Same harness, different decoder

Both notebooks walk a registry of seven models: download, load to GPU, decode, write results to Drive, free the GPU, delete the weights, next. That machinery is not merely similar between them — eight cells are byte-for-byte identical, 18,518 characters reused verbatim.

They diverge at exactly one place: section 4, the algorithm. Everything before it is setup, everything after it is bookkeeping.

Naive beam search

naive-beam-search-colab.ipynb · 33 cells

Keeps 10 hypotheses alive, scores every candidate from every beam on one axis, compares them globally, and re-parents. Commits to a real token every step.

  • Returns 4 ranked sequences
  • Greedy width-1 run as baseline
  • Can stop early once every beam hits EOS

Weighted-embedding feedback

weighted-embedding-feedback-colab.ipynb · 28 cells

Feeds back the probability-weighted average of every embedding row. Nothing is ever chosen, so there is no branching and no text — only a trajectory.

  • 61 configurations per model, one batch
  • Greedy is row 61, not a separate run
  • Never stops early — EOS is recorded, ignored

CORE The one substitution

Strip away the instrumentation and the two experiments differ by a single line — what gets appended to the context each step.

TRAP The scale nobody tells you about

Feeding embeddings instead of token ids is not a neutral swap. It is a second code path through the model, and architectures do not agree on what happens along it — silently, with no error either way.

Three placements of the same multiplier exist in transformers, and two of them need opposite handling from the same config key.

What this would have cost. Falcon-H1R-7B would have run with every fed vector 5.66× too small — no error, no warning, just a quietly degraded trajectory for one of the two hybrid SSM models the experiment exists to compare. The beam notebook is unaffected: it passes input_ids throughout and never leaves the path the models were trained on.

§4 Where the mixtures go

Once nothing is committed, a second question appears that ordinary decoding never has to ask: what does the model see behind the current position? Three answers, run as a full axis.

WHY The mixture is short, and predictably so

A convex combination of vectors pointing in different directions is shorter than any of them. In high dimensions the cross terms cancel and the shortfall follows a law — which is what makes the magnitude axis a real question rather than a hunch.

For mass spread over k effective tokens, the mixture's norm falls as 1/√k of a single token's. Simulated at d=4096, the law holds to three digits.

Effective support is 1/Σp². The effect compounds hardest on last-only rows, where the single short vector is the entire input with no other positions to carry signal — making T4-full-raw-last-only the corner where temperature, tail mass, magnitude and history all push the same way.

Greedy is a configuration, not a separate run. Its "mixture" is one-hot on the argmax — which is both ordinary hard decoding and the exact limit the soft rows approach as temperature goes to zero. Putting it in the batch means it shares the prompt and the step index with everything it is compared against, so divergence is a per-step comparison between rows rather than between runs.

NOW Current state

Neither experiment has data. Both notebooks are code-complete — 82 tests green, ruff clean, outputs cleared, A100 metadata set — and results/ holds only the architectural evidence: architecture-comparison.csv, four tensor-manifest.csv files, and skipped-models.csv.

The beam sweep must be re-run before the comparison means anything. It has run before, but with a prompt that ended "in about 100 tokens" — wording that sent two models into deliberating about whether tokens meant words, and which is now removed from both notebooks. Those results were deleted rather than kept as a misleading baseline. Re-running is ~127 GiB of downloads and roughly an hour.
